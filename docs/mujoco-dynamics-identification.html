ZRCS MuJoCo 动力学辨识详细设计

文档日期：2026-06-25。适用对象：当前工程中的 OpenArm/MuJoCo 在线动力学辨识实现。

当前辨识模块的核心思想是：RT 侧产生安全的多频激励并采集 MuJoCo 关节状态，NRT 侧在线估计每个关节的等效惯量、粘滞阻尼、库仑摩擦和平衡偏置。实现采用递推最小二乘法，模型为 tau = J*ddq + B*dq + Fc*tanh(dq/eps) + bias。

1. 目标和边界

1.1 这个模块解决什么问题

在 MuJoCo 仿真中，同一套轨迹指令会受到关节惯量、阻尼、摩擦、执行器增益、仿真步长和限幅的影响。如果这些参数不合理，就会出现跟踪慢、过冲、抖动、力矩异常、某些关节看起来像“特别重”或“特别软”的现象。

本模块通过主动激励关节，让系统在运行时收集 q、dq、ddq、tau，然后在线拟合每个关节的低阶等效动力学参数。拟合结果可以用于三件事：

  • 判断当前 MuJoCo 模型或控制器参数是否明显不合理。
  • 给 dof_damping、dof_frictionloss、kp、kv 提供自动调参依据。
  • 生成可读报告，快速看出哪个轴没有被激励、哪个轴噪声大、哪个轴结果可信。

1.2 当前实现的边界

当前实现不是完整的机械臂刚体参数辨识。它没有直接估计每个 link 的质量、质心、惯量张量，也没有建立完整的基参数回归矩阵。它估计的是单轴等效模型：

τi ≈ Ji q̈i + Bi q̇i + Fc,i tanh(q̇i/ε) + bi

这个模型适合用于关节级阻尼、摩擦和 PD 增益调优，但不能替代完整逆动力学建模。特别是重力项本来依赖构型 q，当前实现只用常数 bias 吸收局部工作区内的平均重力和静态偏置。

重要限制 如果关节没有运动，或者只在极小范围内抖动，那么 RLS 看到的数据不具备可辨识性。此时即使 RMS 很小，得到的参数也可能完全没有意义。报告工具会把这种轴标为 weak。

2. 整体架构

当前工程把实时控制和辨识计算拆开。RT 侧只做确定耗时的事情：生成激励、推进 MuJoCo、采样、无锁队列推送。NRT 侧做矩阵更新、CSV 写入、状态发布和可选的参数回写决策。

命令入口MoveExcite
生成多频正弦激励。
RT 控制Axis 命令写入控制器，再映射到 MuJoCo servo。
仿真采样MujocoBus
推进 step 并采样状态。
NRT 辨识MujocoIdentifyWorker
消费样本并更新 RLS。
输出/回写CSV、HTML 报告、状态、可选 MuJoCo 参数更新。

2.1 数据方向

方向 通道 数据结构 用途

2.2 运行时顺序

  1. zrcsnrt 启动 RT 子进程，等待共享内存 SharedBlock 就绪。
  2. zrcsnrt/main.cpp 解析 --mujoco-ident-* 参数并启动 MujocoIdentifyWorker。
  3. 用户发送 MoveExcite 命令。
  4. MoveExcite::run() 每个 RT 周期生成目标位置、速度、加速度，并发布到 mujocoIdentCommand。
  5. MujocoBus::send() 先消费最多 8 个参数更新，再调用 simulation_->step()。
  6. MujocoSimulation::fillIdentificationSample() 读取 MuJoCo 状态、控制量、力矩和饱和标志。
  7. MujocoBus 把样本推入 mujocoIdentSampleQueue。
  8. MujocoIdentifyWorker 消费样本，逐轴更新 RLS，写入 mujoco_ident_samples.csv。
  9. 如果开启 apply 且某轴接受样本超过 200，worker 周期性发送 MujocoParamUpdate。

3. 动力学模型

3.1 完整机器人动力学

对 n 自由度机械臂，标准刚体动力学通常写成：

τ = M(q)q̈ + C(q,q̇)q̇ + g(q) + τfric(q̇) + τext

其中 M(q) 是惯量矩阵，C(q,qdot)qdot 是科氏和离心项，g(q) 是重力项，τfric 是摩擦项。完整动力学辨识会把这些项展开成线性参数形式：

τ = Y(q,q̇,q̈)π

Y 是动力学回归矩阵，π 是 link 质量、质心、惯量和摩擦等参数的组合。当前工程没有实现这一级别的全局刚体辨识。

3.2 当前实现的单轴等效模型

当前实现把每个轴局部近似为一个可线性估计的标量模型：

τk = φkT θ + ek
φk = [ q̈k, q̇k, tanh(q̇k/ε), 1 ]T
θ = [ J, B, Fc, bias ]T
参数 物理含义 当前用途 注意事项
J 关节等效惯量或等效 armature。 用于计算建议 kp/kv。当前回写时 applyArmature=0，不会写入 dof_armature。 它不是完整 link 惯量，只是当前数据局部拟合出的标量惯性。
B 粘滞阻尼系数。 开启 apply 时写入 MuJoCo dof_damping。 如果速度激励不足，B 会被噪声污染。
Fc 库仑摩擦幅值，符号由 tanh(qdot/eps) 表示。 开启 apply 时取绝对值写入 dof_frictionloss。 低速附近使用 tanh 平滑，避免符号函数不连续。
bias 常值偏置，吸收局部平均重力、控制偏置或模型偏差。 写入 CSV 和状态，当前不直接回写 MuJoCo。 重力本应随 q 变化，常值 bias 只在小工作区近似有效。

3.3 为什么使用 tanh(qdot/eps)

理想库仑摩擦可写成 Fc * sign(qdot)，但 sign 在 0 附近不连续，低速时容易把噪声放大。当前实现使用：

sign(q̇) ≈ tanh(q̇ / ε)

默认 ε=0.02。ε 越小越接近符号函数，但低速更敏感；ε 越大越平滑，但会把库仑摩擦“抹开”成类似阻尼的效果。

4. RLS 数学推导

4.1 加权最小二乘目标

对某一个关节，假设到第 k 个有效样本为止，目标是最小化指数遗忘加权误差：

Jk(θ) = Σj=1..k λk-j(τj - φjTθ)2

λ 是遗忘因子，当前默认 0.998，并被限制到 [0.90, 0.9999]。越接近 1，历史数据权重越大，估计更稳但跟踪参数变化更慢。

4.2 法方程

令目标函数对 θ 的梯度为 0，可得到：

Rk θk = hk
Rk = Σj=1..k λk-jφjφjT,   hk = Σj=1..k λk-jφjτj

如果每次都显式求逆，代价和数值稳定性都不适合在线运行。RLS 维护协方差矩阵 P = R^-1，每个样本只做小矩阵更新。

4.3 Sherman-Morrison 更新

有递推关系：

Rk = λRk-1 + φkφkT

设 Pk = Rk-1。根据 Sherman-Morrison 公式：

Kk = Pk-1φk / (λ + φkTPk-1φk)
θk = θk-1 + Kk(τk - φkTθk-1)
Pk = (Pk-1 - KkφkTPk-1) / λ

这些公式对应 zrcs_nrt/mujoco_identify/MujocoIdentifyWorker.cpp 中 AxisEstimator::update() 的实现。

4.4 当前代码中的初始化和限幅

项目 当前值 解释
初始参数 theta = {0.02, 0.1, 0.0, 0.0} 初始 J=0.02、B=0.1、Fc=0、bias=0。
初始协方差 P = 1000 * I 较大的不确定性，使前期样本对参数有较大影响。
J 限幅 [1e-5, 1000] 避免负惯量和数值爆炸。
B 限幅 [0, 10000] 避免负阻尼。
Fc 限幅 [-10000, 10000] 估计允许带符号，回写摩擦时取绝对值。
bias 限幅 [-10000, 10000] 防止异常数据使偏置发散。

4.5 样本接受条件

RLS 不会使用所有样本。当前 AxisEstimator::update() 会拒绝以下数据：

  • 轴未使能：enabled == false。
  • 发生限幅或饱和：saturated == true。
  • ddq、dq、tau 不是有限数。
  • 速度过小：abs(dq) < 1e-4。
  • 加速度和速度都太小：abs(ddq) < 1e-3 且 abs(dq) < 1e-3。
  • RLS 分母 lambda + phi^T P phi 非法或过小。

接受样本数用于判断是否可以回写参数。当前 acceptedCount > 200 后，MujocoParamUpdate.valid 才会置 1。

4.6 RMS 误差

每个有效样本的预测误差为：

ek = τk - φkTθk-1

当前 RMS 使用接受样本的累计误差计算：

RMS = sqrt(Σ ej2 / Naccepted)

RMS 小不一定代表结果可信。必须同时看激励幅度、实际运动幅度、饱和比例和接受样本比例。

5. 激励轨迹

5.1 MoveExcite 参数

MoveExciteArg 定义在 zrcs_common/config/CmdDefine.h。参数顺序如下：

序号 参数 默认值或来源 说明
0AxisId必填非负表示单轴；负数 -N 表示激励前 N 个轴。
1Duration20.0持续时间，单位秒。
2Amplitude必填且必须大于 0多频正弦总幅值，OpenArm 单位一般是 rad。
3CenterOffset0.0相对于起点的中心偏移。
4..8F1..F50.15, 0.35, 0.70, 1.10, 1.70多频正弦频率，单位 Hz。
9..13Phase1..Phase50.0, 1.3, 2.1, 0.7, 2.8各频率相位，单位 rad。
14RampTime1.0淡入时间。当前代码只实现开头淡入，不做末端淡出。
15VelScale0.5相对于轴最大速度的安全系数，代码 clamp 到 [0.05, 1.0]。
16AccScale0.5相对于轴最大加速度的安全系数，代码 clamp 到 [0.05, 1.0]。
17SessionId0写入样本，用于区分不同辨识会话。

5.2 多频轨迹公式

MoveExcite 使用 5 个正弦项，权重相同：

wave(t) = A Σi=1..5 (1/5) sin(2πfit + phasei + phaseOffset)

对第 m 个被激励轴，代码使用 phaseOffset = m * 0.73，让多轴同时运动时各轴波形错开。

带淡入包络后的命令位置为：

qcmd(t) = qstart + E(t)(centerOffset + wave(t))

淡入包络使用 smoothstep：

E(t) = s(t/Tramp),   s(x)=3x2-2x3,   0≤x≤1

5.3 解析速度和加速度

速度和加速度不是用差分算出来的，而是直接解析求导：

wavė(t) = A Σ (1/5)(2πfi) cos(2πfit + phasei + phaseOffset)
wavë(t) = -A Σ (1/5)(2πfi)2 sin(2πfit + phasei + phaseOffset)
q̇cmd = Ė(centerOffset + wave) + E wavė
q̈cmd = Ë(centerOffset + wave) + 2Ėwavė + Ewavë

这些量会写入共享内存中的 MujocoIdentCommandData。报告里 qCmd range 和 moving cmd 主要依赖这些命令量。

5.4 安全检查和幅值自动缩小

MoveExcite::init() 会根据轴限位、最大速度、最大加速度检查轨迹是否安全。主要逻辑包括：

  • 当前起点必须在正负限位内。接近限位的 1e-5 误差会被夹到边界。
  • 如果 centerOffset ± amplitude 超出限位，代码会尝试把幅值缩小到可用行程的一半再乘 0.95。
  • 根据多频波形估算最坏速度和加速度，如果超过轴限制，会按比例缩小幅值。
  • 最多尝试 8 次，仍失败则命令初始化失败。
为什么会报 amplitude must be positive Amplitude 是第三个参数，必须显式大于 0。比如只发 MoveExcite 0,30 或把第三个参数留空，都会导致幅值为 0，初始化失败。

6. 采样和共享内存

6.1 MuJoCo 时间步

OpenArm 当前配置： 

<mujocoConfig model="mujoco/robot.xml" timestepMs="10.0" substeps="10">

这表示 ZRCS RT 周期是 10 ms，MuJoCo 内部每个 RT 周期做 10 个 substep，所以 MuJoCo 的内部积分步长为 1 ms：

dtmujoco = timestepMs / substeps = 10 ms / 10 = 1 ms

MujocoSimulation::step() 在每个 RT 周期循环 substeps 次，每次先 applyControls()，再调用 mj_step()。

6.2 采样字段

MujocoIdentSampleData 定义在 zrcs_common/shared_memory/ShmLayout.h。当前实际字段包括：

字段 来源 说明
seqMujocoBus样本序号，RT 侧递增。
commandSeqMujocoIdentCommandData最近一次激励命令状态序号。
sessionIdMoveExcite辨识会话编号。
sampleCountMuJoCo servo 数量本次样本里包含多少个轴。
timestampSecdata->timeMuJoCo 仿真时间。
axisId, slaveIdservo bindingZRCS 轴号和 MuJoCo/驱动从站号映射。
qCmd/dqCmd/ddqCmdMoveExcite 或当前 target如果该轴在 validMask 内，用激励命令；否则用当前保持目标。
q/dq/ddqMuJoCo qpos/qvel/qacc经过 qposScale/qposOffset 转到 ZRCS 用户单位。
tauAppliedqfrc_actuator + qfrc_applied实际施加到该 dof 上的力或力矩。
tauInversemj_inverse由当前 q/dq/ddq 反算出的逆动力学力矩。
ctrlMuJoCo actuator 或手动控制最近一次控制输入。

enabledservo 状态轴是否使能。

6.3 tauApplied 和 tauInverse 的区别

默认 RLS 使用 tauApplied，即控制器实际向 MuJoCo dof 施加的力矩。这更贴近“控制器产生了什么”。如果启动参数带 --mujoco-ident-use-inverse，则改用 tauInverse，即 MuJoCo 根据当前运动状态反算的逆动力学力矩。

力矩源 优点 风险
tauApplied 反映执行器和控制器真正施加的量。 会受 PD 增益、限幅、跟踪误差影响。控制器调得太差时，辨识结果也会被污染。
tauInverse 更接近 MuJoCo 内部动力学需要的力矩。 依赖 MuJoCo 模型本身，如果模型已经错得很厉害，反算力矩也不一定代表真实执行器。

8. 参数回写

8.1 回写触发条件

只有满足以下条件时，NRT worker 才会发送 MujocoParamUpdate：

  • 启动时传入 --mujoco-ident-apply。
  • 某轴 acceptedCount > 200。
  • 距离上次该轴回写至少 applyPeriodSec，当前默认 0.5 s。
  • mujocoParamUpdateQueue 没满，push 成功。

8.2 从辨识参数到 PD 增益

worker 使用二阶系统带宽公式，把等效惯量 J 转成建议增益：

ω = 2π fbandwidth
kp = Jω2
kv = 2ζJω

当前代码对结果做限幅：

  • kp clamp 到 [1.0, 50000.0]。
  • kv clamp 到 [0.0, 10000.0]。

8.3 RT 侧应用到 MuJoCo

MujocoBus::send() 每个周期最多消费 8 个 MujocoParamUpdate，并调用 MujocoSimulation::applyParamUpdate()。当前实际回写：

更新项 写入 MuJoCo 字段 当前是否启用
inertiamodel->dof_armature[dofAdr]默认 applyArmature=0，不写。
dampingmodel->dof_damping[dofAdr]启用。
frictionmodel->dof_frictionloss[dofAdr]启用，使用 abs(Fc)。
kp/kvactuator_gainprm 和 actuator_biasprm启用。
bias无当前不回写，只记录。
建议 调试阶段先不要开 --mujoco-ident-apply。先跑辨识，生成报告，确认轴确实被充分激励且结果合理，再考虑开启在线回写。

9. 使用流程

9.1 推荐流程

  1. 确认 MuJoCo 配置时间步合理。OpenArm 推荐 timestepMs="10.0"，substeps="10"，即内部 1 ms。
  2. 启动 NRT/RT。默认 worker 已启用；需要指定输出目录时加 --mujoco-ident-out。
  3. 先把机械臂移动到远离限位、远离奇异、不会碰撞的姿态。
  4. 对要辨识的轴发送 MoveExcite。
  5. 等待命令结束，停止或继续下一组激励。
  6. 生成 HTML 报告，查看 quality、qCmd range、q range、saturation、RMS。
  7. 只采用 good 或 ok，且运动范围确实足够的轴。

9.2 OpenArm 左臂推荐预备姿态

辨识前建议先移动到一个比较温和的左臂姿态，再进行激励。下面只作为 OpenArm 左臂仿真的起始参考，需要结合当前模型限位确认： 

MoveAbs 0,0.00,0.4,1.5,5
MoveAbs 1,-0.60,0.4,1.5,5
MoveAbs 2,0.00,0.4,1.5,5
MoveAbs 3,1.35,0.4,1.5,5
MoveAbs 4,0.00,0.4,1.5,5
MoveAbs 5,0.00,0.4,1.5,5
MoveAbs 6,0.00,0.4,1.5,5
MoveAbs 7,0.20,0.4,1.5,5

gripper 或行程很小的轴不建议和机械臂主关节一起做动力学辨识。OpenArm 左臂主关节通常优先看轴 0..6。

9.3 发送辨识命令

单轴辨识例子，激励 axis 0，持续 30 秒，幅值 0.03 rad，中心偏移 0： 

MoveExcite
0,30,0.03,0

左臂 7 个主关节一起辨识，使用负数 -7 表示前 7 个轴： 

MoveExcite
-7,30,0.03,0

10. 结果判读

10.1 报告质量标签

tool/identify_report.py 会给每个轴打一个质量标签。当前规则大致为：

标签 含义 是否建议使用
good有足够运动，未饱和，RMS 小于 0.05。通常可用。
ok有足够运动，未饱和，RMS 小于 0.2。可参考，建议结合曲线确认。
noisy有运动，但 RMS 偏大。谨慎使用，通常需要更好的激励或控制参数。
weak没有收到运动命令、命令幅度太小、实际运动太小或有效样本太少。不要使用。
bad饱和比例超过阈值。不要使用。

10.2 必看指标

指标 怎么看
moving_cmd_pct 命令速度或加速度非零的比例。接近 0 表示这个轴根本没有被激励。
qcmd_range 命令位置范围。为 0 或非常小则辨识无效。
q_range 实际位置范围。命令动了但实际没动，说明控制、限位、映射或使能有问题。
saturation_pct 限幅比例。饱和数据被 RLS 拒绝，比例高说明幅值过大或力矩限制太小。
eligible_pct 满足 RLS 更新条件的样本比例。太低说明运动太慢、太小或轴未使能。
rmsError 力矩拟合误差。需要结合力矩量级看，不能单独作为可信度判断。
J/B/Fc/bias 最终估计参数。要看是否和相邻关节量级相近，是否出现极端值。

10.3 你当前那类结果如何读

如果看到类似： 

axis 0 noisy
axis 1 noisy
axis 2 ok
axis 3 noisy
axis 4 good
axis 5 ok
axis 6 ok
axis 7-15 weak

解释是：左臂主关节 0..6 发生了有效运动，其中 2/4/5/6 较有参考价值，0/1/3 噪声或模型不匹配偏大；7 可能是 gripper 或耦合噪声，不能当成主关节动力学参数；8..15 没有被激励，结果不应采用。

11. 故障诊断

11.1 MoveExcite: amplitude must be positive

原因：第三个参数 Amplitude 为 0、缺失或非有限数。正确命令示例： 

MoveExcite
0,30,0.03,0

11.2 negative limit exceeded pos=-0.0000, limit=0.0000

这通常不是辨识算法本身报错，而是控制器命令处理阶段发现某个轴的负限位是 0，而当前位置或命令位置因为浮点误差略小于 0。常见原因：

  • 该轴是夹爪或单向行程轴，负限位确实为 0。
  • 初始位置为 -0.0000，显示上像 0，实际略小于 0。
  • 对行程为 [0, upper] 的轴使用了围绕 0 的正负激励。
  • 轴限位配置不合理，例如上下限都为 0，导致没有可运动空间。

处理方式：不要把夹爪或单向轴纳入主关节动力学辨识；辨识前先把该轴移动到正行程内部，例如 0.2；或者检查配置里的限位。

11.3 报告里某轴 weak

重点看 moving_cmd_pct、qcmd_range、q_range：

  • moving_cmd_pct=0：这个轴没有收到激励命令。
  • qcmd_range=0：命令没有变化，常见于只激励了左臂但看右臂。
  • q_range≈0：命令可能有变化，但实际轴没动，检查使能、映射、限位、控制模式。

11.4 B 或 Fc 特别大

常见原因：

  • 轴没有真实运动，噪声被 RLS 当成阻尼或摩擦。
  • 速度范围太窄，dq 和 tanh(dq/eps) 两个基函数相关性太强。
  • 力矩饱和或执行器限幅，导致实际力矩和模型不匹配。
  • 用 gripper/coupled joint 做单轴模型，物理关系不满足当前假设。

11.5 RMS 大但曲线跟得还行

当前模型没有显式包含完整重力项、科氏项和耦合项。如果运动范围大、姿态变化明显，单轴常偏置模型会吃不下这些非线性项，RMS 会增大。可以尝试：

  • 缩小单次辨识工作区，在多个姿态分别辨识。
  • 降低幅值但延长时间，保证速度/加速度覆盖仍然足够。
  • 改用单轴逐个辨识，减少耦合和控制器互相影响。
  • 后续扩展包含 sin(q)、cos(q) 或完整动力学回归项。

13. 后续改进建议

13.1 从单轴模型扩展到构型相关模型

当前 bias 是常数。如果要改善肩部、肘部这类重力变化明显的关节，可以先加局部重力基函数：

τ = Jq̈ + Bq̇ + Fctanh(q̇/ε) + a sin(q) + c cos(q) + b

这样仍然是线性参数模型，可以继续用 RLS，只是 φ 维度从 4 增加到 6。

13.2 增加协方差和可辨识性指标

报告可以进一步输出 P 的对角线、条件数近似、各基函数相关性。如果某些参数的协方差很大，说明数据不足以辨识该参数，即使 RMS 小也不应该使用。

13.3 将报告生成集成到关闭流程

现在报告需要手动运行 tool/identify_report.py。后续可以在 NRT 停止 worker 时自动生成 HTML，或者在 GUI 中增加“生成辨识报告”按钮。

13.4 更严格的轴选择

MoveExcite -7 适合 OpenArm 左臂主关节，但不同项目的前 N 个轴不一定都是机械臂主关节。可以在配置中增加 identifiable="true" 或辨识轴组，避免误激励 gripper、虚拟轴或限位为 0 的轴。

14. 一句话总结

当前 ZRCS/MuJoCo 动力学辨识是一套面向仿真调参的在线单轴等效模型辨识：RT 负责安全激励和采样，NRT 用 RLS 拟合 J/B/Fc/bias，报告工具负责把大 CSV 变成能看懂的质量判断和曲线。使用时最重要的是保证轴真的被激励、没有饱和、运动范围足够，并且不要把没有运动的轴的参数当成有效结果。
