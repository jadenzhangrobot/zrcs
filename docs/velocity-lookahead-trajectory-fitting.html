ZRCS 速度前瞻与轨迹拟合详解

文档日期：2026-07-13 · 范围：zrcs_nrt/motion/*、zrcs_rt/command/MovePath.* · 关联文档： trajectory-fitting.md、 trajectory-fitting-velocity-feedforward.html、 motion-review.md

本工程的连续路径运动分两层：NRT 侧先把离散路径点拟合成 直线段 + 拐角圆弧段，再做 jerk 受限的速度前瞻；RT 侧对每一段用 1D 弧长 Ruckig 生成平滑进度，并映射成 XYZ 位置命令。几何与全局速度约束在非实时侧完成，实时侧只做确定性执行。

1. 概述与结论

能力 状态 实现位置 说明
轨迹拟合 / 拐角圆角 已实现并接入 PathPreprocessor 折线路径在内部拐角插入圆弧，输出 Line / CircularArc 段。
局部速度限制 已实现 VelocityPlanner3D 全局速度、编程进给、曲率向心加速度共同限速。
段间拐角速度 已实现 calculateJunctionVelocityLimit() 基于夹角、cornerTol、曲率跳变 jerk 约束。
前后向速度扫描 已实现 planSegments() backward/forward scan 保证 S 曲线距离可达。
三次多项式段 代码保留未走主路径 makeCubicSpanSegment() B 样条采样拟合成 cubic 的函数仍在，但当前 fitCornerBlendSegments() 不调用。
RT 弧长执行 已实现 MovePath 1D Ruckig 规划弧长 s，再映射到路径参数 u 与 XYZ。
速度前馈真正下发 接口存在但会被覆盖 Axis::cmdsProcessing() setAxisVelocityCmd() 写入后会被位置差分重算覆盖。详见前馈文档。
设计原则 NRT 负责“看全局、做几何、做前瞻”，RT 负责“看当前段、做平滑执行”。 段与段之间通过 v_exit → TargetVel 与 Ruckig 状态接力保持速度连续。

2. 处理流水线

1. Waypoints 离散 XYZ 点 + 统一 RPY 姿态。
2. PathMoveBlock 相邻点连成原始折线块。
3. PathPreprocessor 过滤零长度段，插入拐角圆弧。
4. VelocityPlanner3D 局部限速 + junction 限速 + 前后扫描。
5. MovePath / MoveL* 打包 RT 命令，弧长 Ruckig 执行。

2.1 调用链

waypoints │ ▼ MotionPreprocessor::process() │ bridge_->setPathMoveConfig(maxVel, maxAccel, maxJerk) │ makeBlocksFromWaypoints() ▼ PathPreprocessor::fitCornerBlendSegments(blocks, cornerTol) │ buildCornerBlends() │ makeLineSegment() / makeArcSegment() │ finalizeGeometry() → length, max_curvature ▼ VelocityPlanner3D::setConfig(...) VelocityPlanner3D::planSegments(segments) │ calculateLocalVelocityLimit() │ calculateJunctionVelocityLimit() │ backward scan / forward scan │ estimateSegmentDuration() ▼ sendSegmentsAsMovePath() 或 sendSegmentsAsMoveL() │ TargetVel = segment.v_exit │ Sync = 1 only for first segment ▼ RT: MovePath::initTrajectory() + applyOutput()

2.2 NRT / RT 职责边界

侧做什么不做什么
NRT 几何拟合、曲率估计、全局速度前瞻、命令打包 不在实时周期内做重计算；不等待每段执行完成
RT 1D 弧长 S 曲线、s→u→XYZ、轴命令下发、倍率控制 不做全局路径重规划；不重新做拐角圆角

3. 数据模型

3.1 分层数据结构

结构角色关键字段
Point3D 纯几何点 x, y, z
PathMoveBlock 原始编程线段 start/end、rx/ry/rz、feedrate
TrajectorySegment 拟合 + 前瞻共用的段表示 几何字段 + 动态字段（见下）

3.2 TrajectorySegment 字段分工

几何阶段写入

  • type：Line / CubicPolynomial / CircularArc
  • coeff[6][4]：轴多项式 c0+c1u+c2u²+c3u³
  • arc_*：圆心、基向量、半径、扫角
  • length：真实弧长
  • max_curvature：最大曲率
  • feedrate_limit：编程进给

速度前瞻写入

  • v_max_local：本段允许最大速度
  • v_enter / v_exit：段首 / 段尾速度
  • a_max_local / jerk_max_local
  • duration：估算执行时间
  • is_lookahead_optimized

3.3 段类型

类型主路径是否产生参数化曲率
Line 是 p(u)=P0+u(P1-P0)，用 coeff 存线性项 0
CircularArc 是 p(u)=C+r[cos(θu)U+sin(θu)V] 1/r
CubicPolynomial 否（预留） 三次多项式，弧长用高斯积分 采样估计 max κ
姿态轴 coeff[3..5] 预留给姿态，但当前拟合阶段对姿态写入常量，不随路径参数变化； MovePath 的姿态 SLERP 输出也处于注释状态。

4. 轨迹拟合（PathPreprocessor）

4.1 入口与过滤

入口函数： 

std::vector<TrajectorySegment>
PathPreprocessor::fitCornerBlendSegments(
    const std::vector<PathMoveBlock>& blocks,
    double cornerTol);

处理步骤：

  1. 只保留 PathMoveType::Line 且长度 > 1e-9 的块。
  2. 还原原始路径点序列 raw = [P0, P1, ..., PN-1]。
  3. 对内部点 P1..PN-2 尝试构造圆角 CornerBlend。
  4. 按“直线残段 + 后续圆角弧”的顺序输出段列表。

4.2 拐角圆弧几何

对内部点 Pi：

vin = normalize(Pi − Pi−1)，  vout = normalize(Pi+1 − Pi)
θ = acos(clamp(vin · vout, −1, 1))

若 θ < 0.01（几乎共线）或 θ > π − 0.01（接近折返），跳过圆角。

切除长度

α = θ/2，  dtol = cornerTol · cos(α) / (1 − cos(α))
dmax = 0.5 · min(|Pi−Pi−1|, |Pi+1−Pi|)
d = min(dtol, dmax)

圆弧参数

S = Pi − d·vin，  E = Pi + d·vout
r = d / tan(α)
n = normalize(vin × vout)，  cdir = normalize(n × vin)，  C = S + r·cdir
U = normalize(S − C)，  V = vin，  sweep = θ
cornerTol 的几何含义 它控制“允许偏离原始拐角顶点的最大弦高/偏差尺度”。 角度越大，同样 cornerTol 下切除长度 d 越小；角度越小（缓弯），d 可以更大。 同时 d 不会超过相邻段长度的一半，避免吃光整条边。

4.3 输出段拼接规则

对第 i 条原始直线块：

  1. 若起点处存在上一拐角圆角，直线起点取该圆角终点；
  2. 若终点处存在下一拐角圆角，直线终点取该圆角起点；
  3. 若直线残段长度 > 1e-9，输出 Line；
  4. 若终点拐角激活，再输出对应 CircularArc。
原始: P0 -------- P1 -------- P2 -------- P3 拟合后: Line(P0 → S1) Arc (S1 → E1) // 绕过 P1 的圆角 Line(E1 → S2) Arc (S2 → E2) // 绕过 P2 的圆角 Line(E2 → P3)

4.4 段几何最终化

finalizeGeometry() 对每段写入：

字段LineCircularArcCubicPolynomial
length 两端欧氏距离 |r · sweep| 8 点高斯-勒让德积分 ∫|p'(u)| du
max_curvature 0 1/r u∈[0,1] 上 33 点采样最大值

4.5 圆弧参数方程与导数

p(u) = C + r [ cos(θu) U + sin(θu) V ]
p'(u) = rθ [ −sin(θu) U + cos(θu) V ]
p''(u) = rθ² [ −cos(θu) U − sin(θu) V ]
κ = |p' × p''| / |p'|³ = 1/r  （圆弧常数）

4.6 进给速度合并

圆角段的进给速度取相邻两直线块进给的“有效合并”： 

// mergeFeedrate(a, b)
if (a > 0 && b > 0) return min(a, b);
return a > 0 ? a : b;

当前 MotionPreprocessor 从 waypoints 建块时，所有块的 feedrate 都设为 cfg.maxVel，因此圆角进给通常等于全局最大速度；真正限制圆角速度的主要是曲率与 junction 约束。

4.7 预留：三次多项式 / B 样条

代码中仍保留：

  • evalClampedCubicBSpline()：5 控制点、clamped cubic B-spline，内部 knot 0.5
  • makeCubicSpanSegment()：在 [u0,u1] 采样 4 点，高斯消元拟合三次多项式
  • fitCubicFromSamples()：解 c1,c2,c3（c0 取 y0）
当前主路径不走 cubic fitCornerBlendSegments() 只调用 makeLineSegment 与 makeArcSegment。 cubic 路径是历史/预留实现，测试与 RT 的多项式 LUT 能力仍可支持，但 NRT 默认不会生成。

5. 速度前瞻（VelocityPlanner3D）

5.1 配置接口

void VelocityPlanner3D::setConfig(
    double max_v,      // 全局最大速度
    double max_a,      // 最大加速度
    double start_v,    // 路径起点速度
    double end_v,      // 路径终点速度
    double corner_tol, // 拐角容差（与拟合共用语义）
    double max_j);     // 最大 jerk

当前 MotionPreprocessor 传入： start_v = 0、end_v = 0，即整条路径“起停”。

5.2 算法总览（planSegments）

  1. 局部限速：对每段算 v_max_local，并写入 a/j 限制。
  2. 初始化 junction 数组：长度 = 段数 + 1。
  3. 几何 junction 限速：相邻段夹角、曲率跳变约束内部节点。
  4. Backward scan：保证能在本段距离内减速到下一 junction。
  5. Forward scan：保证能在本段距离内从当前 junction 加速到下一 junction。
  6. 回写：v_enter、v_exit、duration。
junctionVel indices: 0 1 2 3 4 segments: [seg0][seg1][seg2][seg3] v_enter/v_exit 取相邻 junction Step A: local limit per segment Step B: junction geometry limits Step C: backward reachability (from end to start) Step D: forward reachability (from start to end) Step E: write v_enter, v_exit, duration

5.3 局部速度限制

vmax_local = min( vglobal,  vfeedrate,  vcurvature )

其中曲率限速来自向心加速度约束：

an = v² κ ≤ amax  ⇒  vcurvature = √(amax / κmax)
  • 直线：κ=0，无曲率限速。
  • 圆弧：κ=1/r，半径越小允许速度越低。
  • feedrate_limit ≤ 0 时忽略编程进给限制。

5.4 段间（junction）速度限制

取相邻段端点切向：

tprev = normalize(p'prev(1))，  tnext = normalize(p'next(0))
cosθ = clamp(tprev · tnext, −1, 1)

拐角速度

vcorner = √( amax · cornerTol / max(1 − cosθ, 1e−6) )
vjunction = vcorner · max(0, cosθ)
关于 dir_factor = max(0, cosθ) 当转角 ≥ 90°（cosθ ≤ 0）时，junction 速度被压到 0。 这对“无几何混合的硬拐角”是安全的；但本工程已经插入圆弧圆角时，圆弧本身的曲率限速通常已足够， 该因子在大角度下偏保守。相关讨论见 docs/motion-review.md。

曲率跳变 / jerk 窗口约束

Δκ = |κnext(0) − κprev(1)|
Δamax = jmax · max(0.02 s, cycletime·0.001)
vcurvatureJump = √(Δamax / Δκ)

最终 junction 上限再与两段 v_max_local 取 min。 物理含义：曲率突变导致法向加速度突变，需要用 jerk 能力限制通过速度。

5.5 S 曲线速度过渡模型

前瞻在估算“从一个速度变到另一个速度需要多少距离/时间”时，使用 jerk-limited 模型， 而不是简单匀加速。

过渡时间 transitionTime(v0, v1)

Δv = |v1 − v0|

若三角 jerk 峰值加速度不超过 a_max：

apeak = √(jmax · Δv) ≤ amax  ⇒  T = 2 √(Δv / jmax)

否则进入带恒加速度平台的 S 曲线：

tj = amax/jmax，  ta = Δv/amax − tj，  T = 2tj + ta

过渡距离 dMinTransition(v0, v1)

d = ½ (v0 + v1) · T

这是对单调速度变化的平均速度近似，用于前后扫描中的可达性判断。

最大可达速度 maxReachableVel(v0, distance)

在给定距离内，从 v0 最多能加速到多少。 实现为对目标速度的二分搜索（最多 64 次），判定条件为 dMinTransition(v0, v*) ≤ distance。

5.6 Backward / Forward Scan

Backward（从终点往前）

for i = n-1 .. 0:
  reachable = maxReachableVel(junction[i+1], length[i])
  junction[i] = min(junction[i], reachable)

含义：若后面必须降到某个低速，前面就不能太高，否则本段距离不够减速。

Forward（从起点往后）

for i = 0 .. n-1:
  reachable = maxReachableVel(junction[i], length[i])
  junction[i+1] = min(junction[i+1], reachable)

含义：从当前速度出发，后面节点不能超过本段加速能力。

5.7 段时间估算

estimateSegmentDuration()：

  1. 先算加速到 v_max_local 与从 v_max_local 减速到 v_exit 所需距离；
  2. 若 d_accel + d_decel ≤ length，中间有巡航：
    T = T(venter→vmax) + (L − da − dd)/vmax + T(vexit→vmax)
  3. 否则没有巡航，用二分搜索峰值速度 v*，使 d(v_enter→v*) + d(v_exit→v*) = length，再累加两段过渡时间。
duration 的用途 当前主要是 NRT 侧的估算字段；RT 真正执行时间由 Ruckig 在线规划决定。 它适合调试、日志和上层粗略节拍估计。

6. NRT 集成（MotionPreprocessor）

6.1 配置

struct MotionPreprocessor::Config {
    double maxVel    = 10.0;
    double maxAccel  = 20.0;
    double maxJerk   = 30.0;
    double cornerTol = 0.5;
    bool   galvoMode = false;
};

6.2 process() 主流程

  1. 校验 waypoints ≥ 2，且 RtBridge* 非空。
  2. setPathMoveConfig(maxVel, maxAccel, maxJerk) 写入共享内存，供 RT 读取 a/j 限制。
  3. makeBlocksFromWaypoints()：相邻点 → PathMoveBlock，feedrate = maxVel。
  4. fitCornerBlendSegments(blocks, cornerTol) 生成几何段。
  5. velPlanner_.setConfig(maxVel, maxAccel, 0, 0, cornerTol, maxJerk)。
  6. planSegments(segments) 填 v_enter/v_exit。
  7. sendSegmentsAsCommands()：
    • 默认：sendSegmentsAsMovePath()
    • 振镜模式：仅直线，走 MoveLGalvo

6.3 命令字段映射（MovePath）

v_enter 如何生效？ 命令参数没有单独的 CurrentVel 字段。段首速度依赖： 1) 首段 Sync=1 时强制从 0 开始； 2) 后续段 Sync=0，Ruckig 状态由上一段 pass_to_input() 接力， 而上一段的 TargetVel = v_exit 应等于本段期望 v_enter（前瞻已保证相邻 junction 一致）。

6.4 振镜模式限制

if (cfg.galvoMode && containsNonLineSegment(segments)) {
    // 失败：MoveLGalvo 不能直接执行圆角弧
}

因此振镜模式下若 cornerTol 产生了圆弧，当前会直接报错。 需要要么把 cornerTol 设到不产生有效圆角，要么先把圆弧采样成折线，要么实现 MovePathGalvo。

7. RT 弧长执行（MovePath）

7.1 为什么用 1D 弧长 Ruckig

几何已经固定，RT 只需规划沿路径前进的标量弧长：

s(t) : 0 → Σ Li

每个段把目标位置设为累计弧长 arcOffset_，目标速度设为该段 TargetVel，速度/加速度/jerk 上限来自命令与共享内存。

7.2 段初始化要点

  • Sync==1：清零 arcOffset_ 与 Ruckig 当前 p/v/a。
  • 直线：重建线性系数；圆弧：读取 center/U/V/radius/sweep 并单位化 U/V。
  • 重新计算 geometryLength_（直线距离或 |r·θ|）。
  • 校验命令 Length、Vel、TargetVel 与共享内存 maxAccel/maxJerk。
  • arcOffset_ += geometryLength_，作为本段 Ruckig 目标位置。

7.3 周期输出

geometryS = s − (arcOffset − geometryLength)
u = geometryS / geometryLength  （直线 / 圆弧）
p = evaluate(u)，  T = p'/|p'|，  vxyz = vs · T

位置写入 setAxisPositionCmd，速度写入 setAxisVelocityCmd。 注意：后续轴处理链路会用位置差分覆盖速度命令（见前馈文档）。

7.4 多项式段的弧长 LUT（预留）

若未来启用 cubic 段，RT 会：

  1. 高斯积分求总弧长；
  2. 建立 u→s 查找表；
  3. 执行时用 LUT 反查 + 牛顿迭代求 s→u。

直线与圆弧因参数与弧长线性相关，不需要 LUT。

9. 参数与调参

参数 作用阶段 调大 调小 注意
maxVel 局部限速 + RT Vel 整体更快 整体更慢更稳 当前也用作默认 feedrate
maxAccel 曲率限速 / 拐角速度 / S 曲线 圆弧与加减速更激进 更保守 写入共享内存供 RT 使用
maxJerk 过渡时间 / 曲率跳变 速度变化更陡 更柔和、总时长更长 过小会使短段很难加速
cornerTol 圆角几何 + junction 公式 圆角更大、拐角速度更高 更贴近折线、更慢过弯 过大可能过度削角
galvoMode 命令发送路径 走平台/振镜分解 默认 MovePath 当前不支持圆弧段

9.1 推荐起步值（示例）

MotionPreprocessor::Config cfg;
cfg.maxVel    = 100.0;   // mm/s 或工程统一单位
cfg.maxAccel  = 300.0;
cfg.maxJerk   = 3000.0;
cfg.cornerTol = 1.0;

实际单位需与机床/模型配置保持一致；上表数值来自行为树示例量级，不是通用最优。

10. 工作示例

10.1 三点折线 + 一个拐角

waypoints = {
  {0, 0, 0},
  {100, 0, 0},
  {100, 80, 0}
};

拟合结果通常类似：

Line  : (0,0,0) → 靠近 (100,0,0) 的圆角起点 S
Arc   : S → E   // 绕过 (100,0,0)，约 90°
Line  : E → (100,80,0)

速度前瞻典型特征：

  • 两直线局部限速 ≈ maxVel；
  • 圆弧受 √(a/κ)=√(a·r) 限制；
  • 路径起终点速度为 0；
  • 圆弧入口/出口速度由 junction + 可达性共同决定，不一定等于圆弧局部限速。

13. FAQ / 诊断

Q1：为什么没有圆角？

  • 只有 2 个点：没有内部拐角。
  • 夹角过小/接近 180° 折返：被 θ 阈值跳过。
  • 相邻边太短：d 被压到 < 1e-6。
  • cornerTol 过小。

Q2：为什么拐角速度变成 0？

  • 相邻段切向夹角 ≥ 90°，dir_factor 归零。
  • 终点被配置为 end_vel=0，且靠近终点的段不够长，backward scan 把上游速度一路压下来。
  • 曲率很大（小半径圆弧）导致局部限速极低。

Q3：NRT 规划了 v_enter/v_exit，RT 用了吗？

用了 v_exit（作为 TargetVel）和 v_max_local（作为 Vel）。 v_enter 通过上一段目标速度 + Ruckig 状态接力间接生效，而不是命令显式字段。

Q4：报 MovePath: velocity, acceleration or jerk limit is invalid？

  • 未调用 setPathMoveConfig，共享内存 a/j 无效。
  • 某段 Vel ≤ 0 或非有限数。
  • 手动拼命令时漏了 Length/Vel/TargetVel。

Q5：振镜模式为什么失败？

开启圆角后段序列含 CircularArc，而 MoveLGalvo 只接受直线。 关闭 galvo，或禁用圆角，或先采样。

一句话总结

轨迹拟合把折线变成“直线 + 拐角圆弧”的可执行几何； 速度前瞻在这些段上叠加曲率、夹角、jerk 与距离可达约束，算出每段入口/出口速度； RT MovePath再用 1D 弧长 Ruckig 把这些边界条件平滑执行成连续笛卡尔运动。
