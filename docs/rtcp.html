RTCP 刀具中心点保持

XYZAC 五轴（table-table / TRT）RTCP 演示功能 — 本次 git 修改说明
ShmVersion 15 · CmdId Rtcp=18

1. 这是什么

RTCP（Rotational Tool Center Point，刀具中心点保持）让刀尖在旋转轴 A/C 转动时始终停留在同一个工件坐标点上。 本次改动为 XYZAC 五轴机床新增了一条一次性 RT 指令 Rtcp：开启后锁定当前刀尖对应的工件点， 然后自动演示一段 A/C 摆动轨迹，每个周期用运动学反算把刀尖拉回锁定点，实现 XYZ 同步补偿。

运动学模型

新增轻量 TRT 运动学 MachineToolXyzac，无需继承 RobotModel。

RT 指令

新增 Rtcp 命令节点，用 Ruckig 规划 A/C 轨迹并逐周期补偿 XYZ。

共享内存

新增 RtcpCtrl 状态块，NRT/RT 通过原子变量交换锁定点与开关。

GUI 入口

点动面板新增「RTCP 演示」勾选框，下发 Rtcp 命令。

2. 在加工中的作用

五轴加工里,旋转轴(A/C)的作用是调整刀具相对工件的姿态(法向对刀、避免干涉、侧刃切削)。 但旋转轴的回转中心(pivot)通常并不在刀尖上——转台一转,刀尖就会绕着回转中心画出一段圆弧,离开原来的切削点。

没有 RTCP

程序里 A/C 一变,刀尖位置随之偏移,必须由 CAM 后处理把每个点的 XYZ 都算进去。换刀长、改姿态就得重新后处理。

开启 RTCP

数控系统实时补偿:程序只需给出刀尖在工件上的目标点 + 刀轴姿态,XYZ 由控制器自动跟随,刀尖始终贴着编程点。

具体价值:

  • 编程解耦 — CAM 按刀尖轨迹(工件坐标)编程,与机床结构、刀长无关。同一程序换机床/换刀只改参数,不重新后处理。
  • 手动示教/对刀友好 — 摇动 A/C 找姿态时刀尖不跑位,便于贴合曲面、找法向。本次的演示指令正是展示这一点:锁定刀尖后摆动 A/C,刀尖钉在原地。
  • 精度 — 补偿在插补周期内完成,回转误差不累积到工件轮廓;刀长变化只改一个参数。
  • 表面质量 — 姿态平滑变化时刀尖轨迹连续,避免因回转导致的过切/欠切。

3. RTCP 数学原理

RTCP 的核心是一个约束:无论旋转轴怎么转,刀尖在工件坐标系里的点 p_work 保持不变。 控制器每个周期做的,就是解一个逆运动学——已知 p_work 和当前旋转角,反求平动轴 XYZ。

3.1 通用形式

设刀尖在机床世界坐标系(machine base)的位置为 tip_world,平动轴贡献 d(X,Y,Z), 旋转轴把工件坐标系变换到世界坐标系的位姿为 T_wc(θ)(θ 为旋转轴角度)。刀尖同时属于"刀侧"和"工件侧",于是有一致性约束:

tip_world = f_tool(X, Y, Z)  =  T_wc(θ) · p_work

左边是刀具链(平动轴 → 刀尖),右边是工件链(旋转轴 → 工件上的锁定点)。RTCP 就是在 p_work 与 θ 已知时解出左边的 XYZ:

(X, Y, Z) = f_tool⁻¹ ( T_wc(θ) · p_work )

3.2 三类结构

结构旋转轴在说明
Head-Head (RRT)刀侧(主轴摆头)回转让刀尖摆动,补偿量含摆长(pivot 到刀尖距离)
Table-Table (TRT)工件侧(双转台)回转让工件动,刀尖不动;补偿是把编程点随台面变换回来 —— 本机型
Head-Table各一个混合,刀侧摆 + 台侧转

本项目是 XYZAC 双转台(TRT):A 绕 X、C 绕 Z,均作用于工件台,主轴垂直不摆。

3.3 本机型推导(XYZAC / TRT)

工件坐标系到世界坐标系的位姿由旋转轴链串联而成(右乘顺序即从工件侧往世界侧读):

T_wc(A, C) = Trans(pivot) · RotX(A) · Trans(tableOffset) · RotZ(C)

其中各 4×4 齐次矩阵为:

          ⎡1        ⎤          ⎡1              ⎤          ⎡cosC −sinC     ⎤
RotX(A) = ⎢  cA −sA ⎥  RotZ(C)=⎢  cosC −sinC   ⎥→（绕Z）⎢sinC  cosC     ⎥
          ⎢  sA  cA ⎥          ⎢  sinC  cosC   ⎥          ⎢          1    ⎥
          ⎣        1⎦          ⎣            1  ⎦          ⎣            1  ⎦
                        （cA=cosA, sA=sinA；RotX 绕 X 轴）

Trans(t) = I₄ 的第 4 列置 (tx, ty, tz, 1)

正解:锁定点经台面变换得到刀尖世界坐标,再由垂直主轴几何得到关节 XYZ(Z 正方向朝下):

tip_world  = T_wc(A,C) · [p_work; 1]        // workToWorld
X = tip_world.x
Y = tip_world.y
Z = toolTipZ0 − tip_world.z                 // zPositiveDown 反解

锁定(取 p_work):开启 RTCP 那一刻,用当前关节值反推工件点并存下来:

tip0     = ( X₀, Y₀, toolTipZ0 − Z₀ )        // toolTipWorld(当前 XYZ)
p_work   = T_wc(A₀, C₀)⁻¹ · [tip0; 1]        // worldToWork

之后无论 A/C 怎么动,p_work 不变,每周期用 rtcpXyz(p_work, A, C) 重算 XYZ,即完成补偿。 代码对应 MachineToolXyzac::tablePose / workToWorld / worldToWork / rtcpXyz。

直觉:TRT 结构下"刀尖不动、工件在转"。把工件想成一张贴着锁定点的转台,台子绕 A/C 转了, 控制器就反向把平动轴 XYZ 挪一挪,让垂直主轴的刀尖重新对准转过去的那个点 —— 相对工件看,刀尖纹丝不动。

3.4 行程约束

补偿量受平动轴行程限制。A 倾角越大,刀尖绕 pivot 画的弧越大,需要的 Z 补偿越多。 本演示把 A 软限位在约 ±25°(softMax = 0.45 rad),保证反算出的 Z 落在 [0, 0.40] 行程内,针尖接触约在 z = 0.16。 实际加工中,若姿态需求超出行程或触发奇异(如 A 接近 ±90° 时 C 方向不定),需要在 CAM 侧规划或做奇异规避。

4. 坐标与运动学模型

模型定义在 zrcs_rt/model/MachineToolXyzac.h / .cpp，几何与 config/5axis/mujoco/robot.xml 保持一致。单位为米 / 弧度。

刀尖正解（垂直主轴）

Z 轴正方向朝下（CNC 风格，zPositiveDown = true），对应 MuJoCo 中 axis 0 0 -1：

tip_world = ( X, Y, toolTipZ0 − Z )

工作台位姿（table pose）

工件坐标系 → 机床世界坐标系的齐次变换，A 绕 X 转、C 绕 Z 转：

T(a, c) = Trans(pivot) · RotX(A) · Trans(tableOffset) · RotZ(C)

其中 pivot = (0, 0, 0.38) 为 A 轴摆动中心，tableOffset = (0, 0, 0.05) 为 pivot 到转台面中心的偏移， toolTipZ0 = 0.70 为 Z=0 时刀尖世界高度。

RTCP 反解

锁定的工件点 p_work 加上目标 A/C，反算需要的机床 XYZ 指令：

rtcpXyz(p_work, a, c) :
    tip_world = T(a, c) · p_work        // workToWorld
    X = tip_world.x
    Y = tip_world.y
    Z = toolTipZ0 − tip_world.z         // worldTipToXyz (zPositiveDown)
方法作用
tablePose(a, c)返回工作台 4×4 齐次位姿矩阵
workToWorld(pWork, a, c)工件点 → 世界坐标
worldToWork(pWorld, a, c)世界坐标 → 工件点（锁定时用，取 T⁻¹）
toolTipWorld(x, y, z)关节 XYZ → 刀尖世界坐标
worldTipToXyz(tip, x, y, z)刀尖世界坐标 → 关节 XYZ（反解）
rtcpXyz(pWork, a, c, x, y, z)RTCP 主入口：锁定点 + A/C → 机床 XYZ

5. Rtcp 指令

定义在 zrcs_rt/command/Rtcp.h / .cpp，注册为 REGISTERCMD(Rtcp)，CmdId = 18。

参数（RtcpArg）

索引参数含义
0Enable1 = 锁定当前刀尖并开始演示；0 = 关闭（立即返回 SUCCESS）
1ToolLength预留刀长（m），写入 rtcpCtrl.toolLength

执行流程

init()  → 复位 locked_ / active_ / wpIndex_
run() 首帧  → lockWorkPoint()
    读取 A0/C0 与当前 XYZ  → toolTipWorld  → worldToWork  → 得到 p_work
    写入 shm.rtcpCtrl（pWork / lockValid=true / enabled=true）
    buildDemoWaypoints()  → 生成 6 个 A/C 航点
run() 每周期  → otg_.update() 规划 A/C  → setAxisPositionCmd(A,C)
    applyRtcpXyz(a, c)  → rtcpXyz 反算  → setAxisPositionCmd(X,Y,Z)
    段完成 → 切下一航点；6 段跑完 → 关闭并 SUCCESS
exit()  → enabled=false, lockValid=false, 复位状态

演示航点

buildDemoWaypoints() 生成 6 段 A/C 动作，A 倾角经 clampA 软限位在约 ±25°（softMax=0.45 rad）， 避免大倾角把针尖甩出 Z 行程 [0, 0.40]。C 从起点依次转到 +60° / +120° / 180° / +240° / +300°，最后一段 A/C 回到起点。 每段用 setupSegment() 配置 Ruckig 的速度/加速度/jerk（演示用中等速度，便于观察球面跟踪）。

Rtcp 是一次性演示指令：开启后自动跑完 6 段就关闭并返回 SUCCESS。它不是持续跟随外部 A/C 输入的常驻 RTCP 模式。

6. 共享内存 RtcpCtrl

zrcs_common/shared_memory/ShmLayout.h 新增 RtcpCtrl 块， kShmVersion 由 14 升到 15（ABI 变更，NRT 与 RT 必须同版本重编）。 

struct alignas(64) RtcpCtrl {
    std::atomic<bool>   enabled{false};   // 是否补偿
    std::atomic<bool>   lockValid{false}; // 锁定点是否有效
    std::atomic<double> toolLength{0.0};  // m，预留
    std::atomic<double> pWorkX{0.0};      // 锁定工件点
    std::atomic<double> pWorkY{0.0};
    std::atomic<double> pWorkZ{0.0};
};
ShmVersion 已从 14 升到 15。升级后务必重新编译并重启 NRT 与 RT，否则会因 magic/version 校验失败而拒绝挂载共享内存。
