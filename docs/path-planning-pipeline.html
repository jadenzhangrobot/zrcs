ZRCS 路径规划流水线文档

本文档描述 zrcs_nrt/algorithm/path_planning 模块： 如何把 waypoints / NC 折线变成「几何段 + 速度前瞻结果」，供行为树与 RT 路径运动使用。

减点 → 拐角 → 短段合并 → 前瞻 对齐 LinuxCNC G64 P/Q 思路 纯算法，无 RT/ZMQ 依赖

1. 总览

路径规划模块解决的核心问题：CAM/NC 输出的密折线不能直接高速连续切削—— 微段过多、假拐角多、真拐角又需要容差过渡，且必须在动力学约束下规划速度。

模块边界：

  • 输入：std::vector<Point3D> 或 PathMoveBlock[]（通常由 core/nc_parser/NcParser 产出）
  • 输出：TrajectorySegment[]（Line/Arc 几何 + v_enter/v_exit 等）
  • 下游：PathMoveSupport 转成 RT MovePath 命令
  • 不做：G 代码词法解析、实时插补、Ruckig OTG（在 RT 侧）
单位约定（5axis 配置下）：位置 mm，速度 mm/s，姿态 rad。 容差参数与路径单位一致。

4. ① 路径简化 — PathSimplifier

PathSimplifier.h / .cpp

对应 LinuxCNC Naive CAM Detector（G64 Q）： 折叠近共线中间点，减少 CAM 密化微段。

算法：collapseCollinearWaypoints

  1. 维护 anchor（已确认保留的链起点）
  2. 对每个候选中间点 i，检查 [anchor+1 .. i] 到弦 [anchor, i+1] 的垂距是否都 ≤ collinearTol
  3. 且相邻进给足够接近（相对误差 ≤ 1e-9 量级）
  4. 满足则丢弃中间点；否则在 i 处断链并输出
原始: A · b · c · d · E · F 垂距(b,c,d 到 AE) ≤ Q 且进给一致 折叠后: A ──────── E · F
注意：本步不按段长剔除。 再短的段，只要方向拐了或进给变了，都会留下。 短段处理在第 ③ 步合并。

算法：mergeShortLineSegments

段级贪心合并（也被 ShortSegmentMerger 调用）：

  • 只合并直线，圆弧打断合并链
  • 必须首尾相接
  • 近共线：cosθ > 0.999（约 <2.5°）
  • 或过短强制：当前长 < minSegLen 且 cosθ > 0.98
  • 非 shortMerge 时还要满足弦高 ≤ collinearTol
  • 进给取 min；最后滤掉 length ≤ 1e-9 的数值零长段

5. ② 拐角处理 — CornerBlender

CornerBlender.h / .cpp

对应 G64 P：在真拐角插入与两侧直线相切的圆弧， 使路径偏离原角点不超过 cornerTol。

几何关系

入边方向 vIn，出边方向 vOut，转角 θ = angle(vIn, vOut) 半角 α = θ/2 截断距 d：从角点沿入/出边回退距离 半径 R = d / tan(α) 路径偏差 δ 与 d 的关系： d = δ · cos(α) / (1 - cos(α)) （δ = cornerTol） 实际 d = min(d_tol, d_max) d_max = 0.5*min(lIn,lOut) - minRemain 保证两侧至少留下 minSegLen 直线

跳过圆角的情况

  • 近共线（θ 很小）或近折返（θ 接近 π）
  • 入/出弦过短：min(lIn,lOut) < minChordForBlend（默认 4×minSegLen）
  • 算得 d 过小或半径/法向退化

输出结构

对每段边输出「截断后的直线」；在启用圆角的角点后插入 CircularArc。 圆角进给取相邻两段进给的 min。

6. ③ 短段合并 — ShortSegmentMerger

ShortSegmentMerger.h / .cpp

圆角后可能留下过短直线残段。本阶段调用 PathSimplifier::mergeShortLineSegments，并重编号 segment_id。

名字刻意不用 “Smoother”：这里不是样条/G2 连续平滑，而是几何清理。 真正“平滑感”主要来自第 ② 步的圆弧过渡。

7. ④ 速度前瞻 — LookAheadPlanner

LookAheadPlanner.h / .cpp

步骤

  1. 段内上限：v_max = min(全局, 进给, √(a/κ))
  2. 接点几何限速：拐角容差模型 + 曲率跳变 jerk 限制
  3. 反向扫描：保证能减速到后续接点
  4. 正向扫描：保证能从入口加速到后续接点
  5. 写回 v_enter / v_exit / duration

拐角限速模型

// 切向夹角 θ，路径容差 cornerTol
v_corner ≈ sqrt( maxAccel * cornerTol / (1 - cosθ) )
v      *= max(0, cosθ)   // 大折角/反向更慢

// 曲率跳变：Δa ≈ v²·Δκ ≤ jerk * Δt
v_curv = sqrt( (jerk*Δt) / Δκ )
limit  = min(v_corner, v_curv, maxVel)

速度切换距离

使用简化 S 曲线：在 jerk 与加速度约束下计算 transitionTime(v0,v1)， 最短距离 dMin = 0.5*(v0+v1)*T。 双向扫描用二分求「在段长内可达的最大速度」。

控制周期默认 ZRCS_CYCLE_TIME_MS=10（CMake 可注入）， 用于曲率跳变的最小时间窗。

10. 参数建议

场景cornerTol说明
精加工较小（如 0.01–0.1 mm）贴形，速度更保守
粗加工较大（如 0.2–1 mm）更圆滑、更快
密化自由曲线配合显式 minSegLen默认 3×cornerTol 可能大于弦长，导致不做圆角
蝴蝶线类路径：若 cornerTol=0.25 且用默认 minSegLen=0.75，则 minChordForBlend=3.0， 弦长短于此值时全部跳过圆角。测试中需显式传入合适的 minSegLen。

minSegLen 应明显大于「控制周期 × 典型进给」： 周期 10 ms、进给 150 mm/s 时一周期约 1.5 mm，微段远小于此会拖垮 OTG。
