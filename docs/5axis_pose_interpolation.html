ZRCS / 5axis / xyzac_table

姿态插补与 RTCP 全链路

从 NC 的 XYZAC 指令、逐点姿态、NRT 路径规划与发令，到 RT 标量轨迹、A/C 连续展开、XYZAC 逆解和五轴命令输出。本文以当前仓库实现为准，同时标明尚未纳入在线规划的姿态约束。

文档日期：2026-07-24 内部单位：m / s / rad 目标模型：XYZAC 转台式五轴 示例：R40 球面连续六边形网格

1. 结论摘要

当前实现已经完成“逐点 XYZAC 输入、位置与 A/C 共用进度参数、每周期 RTCP 逆解”的五轴联动闭环，但速度前瞻仍然是纯 XYZ 路径前瞻。

已实现：逐点姿态

每个路径点对应一个 PathOrientation{rx, ry, rz}。NC 的 A/B/C 以度输入，解析后统一为弧度。

已实现：同步五轴插补

RT 用一个 Ruckig 标量弧长轨迹生成 u，XYZ、A、C 都由同一个 u 求值，不会各轴独立计时。

已实现：RTCP 逆解

每个控制周期把工件坐标中的刀位点和 A/C 姿态变换到机床世界坐标，输出 XYZAC 五个轴命令。

已实现：段内刀轴 SLERP

XYZAC 执行时从段端 A/C 得到工件坐标系刀轴，沿最短大圆进行 SLERP，再选择靠近连续参考分支的等价 A/C 解。

当前行为：姿态不参与前瞻

局部限速、拐角限速、正反向扫描只使用 XYZ 长度、切向、曲率、F、最大线加速度和 jerk。

风险：轴约束依赖离线保证

MovePath 没有在前瞻阶段检查 A/C 及 RTCP 耦合后的 XYZ 轴速度。超限后 Axis 层会限速或钳位，可能破坏刀尖轨迹同步。

对当前球面加工程序的判断 sphere_hex_grid.nc 通过小于等于 0.5 mm 的离散步长、5 mm/s 进给、连续 C 角和离线轴速检查来规避在线前瞻缺口；测试阈值为球面误差小于 0.010 mm、法向误差小于 0.041°、A/C 速度不超过轴配置。

非实时阶段：解析

NcParseNode 解析 NC，输出严格对齐的点、姿态和边进给三个数组。

非实时阶段：规划

PathMoveNode 调用 MotionPlanner 生成几何段，并给每段写入入口/出口速度与加速度。

跨域发令：逐段打包

PathMoveSupport 把段端点姿态转换为四元数，按 MovePathArg 顺序下发；第一段 Sync=1，后续段为 0。

实时阶段：标量轨迹

MovePath 用一自由度 Ruckig 生成累计弧长 s(t)，并由当前段弧长归一化得到 u。

实时阶段：RTCP 输出

用同一 u 求位置和 A/C，调用 XyzacTableRobot::inverseKinematics，把结果写入五个轴。

姿态处理的职责边界 MotionPlanner 不读取逐点姿态；PathMoveSupport 只把段端 A/B/C 编码为 q0/q1；真正的段内 A/C 插补在 RT MovePath 中完成。当前三个阶段都没有把姿态导数或 RTCP 后五轴导数纳入速度前瞻。

3.1 三种坐标含义

工件坐标 pwork

NC 的 XYZ 是加工点在随转台转动的工件坐标系中的坐标。球面示例的球心为 (0, 0, 0.070) m，半径为 0.040 m。

机床世界坐标 tipworld

固定主轴刀尖在机床中的目标位置。A/C 转动工件后，XYZ 直线轴必须补偿，使刀尖仍落在指定工件点上。

Twork→world(A,C) = Tbase · Rx(A) · Ttool · Rz(C)
tipworld = Twork→world(A,C) · [pwork, 1]T
qXYZ = tipworld − jointOffsetXYZ

当前模型参数为 Tbase.z = 0.38 m、A 到 C 原点偏置 Ttool.z = 0.05 m、Z 轴关节偏置 0.60 m。主轴自身不随 A/C 旋转；旋转块是路径协议和转台姿态的编码。

3.2 RPY 与物理旋转链

NRT 的 rpyToQuaternion 使用常规 RPY 组合：

Rprotocol = Rz(C) · Ry(B) · Rx(A)

XYZAC 机型只接受 B=0 的姿态。RT 从协议旋转中恢复 A/C 后，为物理转台模型构造：

Rmachine = Rx(A) · Rz(C)
为什么旋转次序看起来不同 四元数封包沿用通用 RPY 接口；XYZAC 逆解消费的是物理链 Rx(A)·Rz(C)。RT 中间的“提取 A/C，再按物理链重建”正是这两种表示之间的适配层。

4. NC 解析与逐点姿态生成

4.1 模态状态

NcParser 在逐 block 扫描时保持位置 pos、姿态 orientation、G90/G91、G20/G21、当前运动方式和模态 F。没有在当前行出现的轴保持上一值。

// 概念等价代码
target = pos;
targetOrientation = orientation;

if (G90) {
    X/Y/Z = 程序长度单位 → m;
    A/B/C = degree → rad;
} else { // G91
    target += ΔXYZ;
    targetOrientation += ΔABC;
}

waypoints[i]     ↔ orientations[i]
feedrates[i]     ↔ edge(waypoints[i], waypoints[i+1])

4.2 G0/G1

直线块直接追加目标位置和目标姿态。G0 的段进给写为 0，后续规划使用 PathMove.maxVel 回退；G1 使用当前模态 F。

4.3 G2/G3

当前圆弧解析在 XY 平面按弦高误差离散，Z 线性变化。每个离散点的 A/B/C 也按采样比例做分量线性插值：

rpy(t) = rpy0 + t · (rpy1 − rpy0),   t∈[0,1]

这一步没有做角度归一化或最短弧处理，因此生成 NC 时应先把 C 角展开成连续序列。

仅姿态变化的 NC block 当前不会生成轨迹点 appendIfMoved 只有在 XYZ 距离大于极小阈值时才追加点。只有 A/B/C 改变而 XYZ 不变的 block 会更新模态姿态，但不会形成可执行的纯旋转段。需要纯旋转时，应新增专用旋转命令或允许零长度姿态段，而不是依赖现有 MovePath。

4.4 三个数组的不变量

orientations.size() = waypoints.size()
feedrates.size() + 1 = waypoints.size()

解析末尾会修正数组长度。姿态随点，进给随边，这是后续逐段打包的核心契约。

5. NRT 路径拟合与速度前瞻

5.1 当前几何流水线

  1. makeBlocksFromWaypoints：把相邻点转为直线 block，并挂接每条边的 F。
  2. PathSimplifier：按共线容差折叠冗余点。
  3. CornerBlender：按拐角容差生成直线与圆弧过渡。
  4. ShortSegmentMerger：合并过短段。
  5. LookAheadPlanner：计算局部上限、接点速度、正反向可达速度和接点加速度。

5.2 前瞻使用的量

约束当前公式/依据是否考虑姿态

曲率限速v ≤ sqrt(maxAccel / curvature)只用 XYZ 曲率

5.3 带逐点姿态时的保护机制

规划器本身不接收 orientations。规划结束后，queuePathFromWaypoints 会验证：

  • 姿态数量必须等于原始 waypoint 数量。
  • 规划段数量必须等于原始边数量。
  • 每一段的起终点必须与对应原始边一致，误差不大于 1e-8 m。

只要简化、圆角或短段合并改变了点边对应关系，整条路径拒绝下发。这保证了姿态不串点，但也意味着当前姿态路径不能直接使用几何拟合。

球面加工配置为什么是 0 Cmd_NcMapleCarve 和 Cmd_NcSphereHexGrid 使用 cornerTol="0.0"、minSegLen="0.0"，从而保留离线生成的每一条 XYZAC 边。代价是当前拐角限速公式在 cornerTol=0 时对所有内部接点给出 0 速度，约 0.5 mm 的每个短段都会变成一次停走循环，A/C 速度表现为密集脉冲。曲面精度得到保护，但连续加工速度并未得到保护。
cornerTol = 0 ⇒ vcorner = sqrt(a·cornerTol/(1−cosθ)) = 0 ⇒ vexit,i = 0

6. 姿态编码与 MovePath 发令

6.1 欧拉角转四元数

PathMoveSupport::rpyToQuaternion 按常规 RPY 公式生成并归一化四元数：

cr = cos(rx/2), sr = sin(rx/2)
cp = cos(ry/2), sp = sin(ry/2)
cy = cos(rz/2), sy = sin(rz/2)

qw = cr·cp·cy + sr·sp·sy
qx = sr·cp·cy − cr·sp·sy
qy = cr·sp·cy + sr·cp·sy
qz = cr·cp·sy − sr·sp·cy

有逐点姿态时，第 i 段直接使用 orientation[i] 和 orientation[i+1]。没有逐点姿态时，先按累计 XYZ 弧长在全局起终 RPY 之间线性取段端姿态，再转换为四元数。

SLERP 在 RT 段内执行 NRT 计算并传递段端四元数；XYZAC RT 恢复 A/C 后构造端点刀轴，用 Identity.slerp(u, delta) 沿球面最短大圆求值。它插补的是两自由度刀轴方向，不是给两旋转轴强行加入第三个不可实现的姿态自由度。

7. RT 中的位置与姿态同步插补

7.1 一自由度路径标量

MovePath 的 Ruckig 实例只有 1 个自由度。它规划的不是任一物理轴，而是累计路径弧长 s：

starget = sprevious + Lsegment
u(t) = [s(t) − (starget − Lsegment)] / Lgeometry

第一段收到 Sync=1 时，当前位置、速度、加速度和累计弧长清零；后续段沿用上一段的 Ruckig 状态，从而实现 v_exit/a_exit 连续。

7.2 位置求值

直线：p(u) = p0 + u(p1 − p0)
圆弧：p(u) = center + r[cos(θu)·er + sin(θu)·et]

7.3 XYZAC 姿态求值

RT 首先归一化端点四元数，恢复协议中的 A/C，并检查旋转矩阵能否由 Rz(C)·Rx(A) 精确表示。若存在 B 分量或其他不可表示旋转，误差超过 1e-8 即失败。

dtool(A,C) = Rz(−C)·Rx(−A)·ez
d(u) = Slerp[d0, d1, u]

随后从 d(u) 求两组等价 A/C，选择最靠近连续参考分支的一组；极点处 C 为自由坐标，沿端点展开后的参考 C 连续过渡。

targetPose(u) = { Rx[A(u)]·Rz[C(u)], p(u) }

同步的含义

XYZ、A、C 共用一个 u(t)。若路径减速，旋转也按相同比例减速；若路径在段末保持非零速度，姿态也连续到下一段。

同步不等于受约束

共用 u 只保证时间配准，并不自动保证 A/C 或 RTCP 后 XYZ 的速度、加速度、jerk 都在轴限制内。

7.4 非 XYZAC 模型

若模型不是严格的五自由度 xyzac_table，当前 MovePath 只输出前三个 XYZ 轴；虽然仍会校验四元数有效性，但不会执行姿态插补。因此本文的五轴结论只适用于模型类型和关节顺序都匹配的 XYZAC 模型。

8. XyzacTableRobot 的 RTCP 逆解

8.1 机型识别

MovePath 只有在以下条件全部满足时启用 RTCP：

  • 模型类型为 xyzac_table，DOF 为 5。
  • 关节顺序为 X、Y、Z 三个移动关节，随后是绕 X 的 A 和绕 Z 的 C。
  • 模型轴映射数量与 DOF 一致。

8.2 旋转角提取和分支选择

逆解从物理旋转矩阵 Rx(A)·Rz(C) 提取：

A = atan2(−R1,2, R2,2)
C = atan2(−R0,1, R0,0)

提取后重新构造旋转矩阵并校验误差。接着使用当前关节位置作为参考，把角度加减整数个 2π，选择最近的等价分支：

unwrapNear(θ, θref) = θ + 2π · round[(θref − θ)/(2π)]

8.3 直线轴补偿

给定工件坐标点和 A/C，逆解计算世界坐标刀尖，再减去关节偏置：

modelA = A + offsetA
modelC = C + offsetC

tipWorld = baseTf · RotX(modelA) · toolTf · RotZ(modelC) · pWork

Xcmd = tipWorld.x - offsetX
Ycmd = tipWorld.y - offsetY
Zcmd = tipWorld.z - offsetZ
Acmd = unwrap(A - offsetA, currentA)
Ccmd = unwrap(C - offsetC, currentC)

MovePath::solveRtcp 每个 RT 周期调用一次逆解，以上一周期目标关节作为下一次种子，并只向五个位置控制轴写入位置目标。Axis 命令整形阶段仍会根据相邻位置命令计算内部速度，用于轴级限速和状态反馈。

IK 成功不等于轴限位检查通过 XyzacTableRobot::inverseKinematics 只检查尺寸、旋转可表示性和数值有限性，不读取 axis.xml 的软限位。软限位在 Axis 命令整形阶段处理；加工前仍应在 NRT 或离线阶段完整扫描轴位置和轴导数。

9. C 轴展开、跨 ±180° 与奇异区

9.1 连续 C 角

NC 解析器不会把角度压回 [-π, π]。例如球面网格中的 C 可以连续经过 -180°、-182.2°，末尾也可到 210°。RT 再以当前/上一姿态为参考做 unwrapNear，跨 ±180° 时选择最近等价角。

单段旋转必须小于 180° 才能可靠保留方向 四元数只表示最终空间旋转，不携带“绕了几圈”的拓扑信息。若一个段的 C 增量大于 180°，RT 的最近分支展开可能选择反方向的等价姿态。连续多圈必须拆成增量小于 180°的多个点，并同时满足 C 轴总软限位。

9.2 球面极点

当刀位法向接近 +Z 时，保持刀轴沿法向只要求 A 接近 0，而 C 对刀轴方向几乎没有影响。这里是“法向定向任务”的参数退化区，不是矩阵求解失败。工业做法通常是：

  • 从上一点延续 C，而不是每点独立用 atan2 取主值。
  • 把分支选择写成带轴限位、剩余行程和速度代价的连续优化。
  • 在极点附近降低 C 的变化权重或冻结 C，离开极点后平滑恢复。

9.3 当前球面法向构造

对球面单位法向 n=(nx,ny,nz)，当前程序选择 A/C，使：

Rx(A) · Rz(C) · n = [0,0,1]T

生成器必须对 C 做连续展开，随后检查 A∈[-1.920,1.920]、C∈[-6.2832,6.2832]。当前可达球冠截止到极角 85°，给 A 轴 ±110° 留有余量。

9.4 软限位的实际后果

Axis 层根据剩余距离计算制动速度 sqrt(2as)，并按轴最大速度/加速度整形；到边界后只锁止继续越界的方向。这个安全网会改写某一个物理轴的本周期目标，而 MovePath 内部仍按原来的 s(t) 前进，因此一旦触发，严格 RTCP 同步已被破坏。加工路径不能把软限位当作正常规划器使用。

10.1 第一条切削边如何执行

  1. NC 位置从 mm 转为 m，A/C 从 degree 转为 rad，F 转为 0.005 m/s。
  2. NRT 保留该边的起终点，不做圆角或短段合并。
  3. A/C 端点编码为两个四元数，连同直线端点和前瞻速度边界下发。
  4. RT 由路径弧长计算 u，得到直线弦上的 p(u)，并用刀轴 SLERP 和连续分支求出 A(u), C(u)。
  5. 每周期将球面工件点经转台变换为世界刀尖位置，输出 XYZAC。

10.2 为什么用密集短弦

位置沿球面端点之间的直线弦插补，刀轴方向沿端点间最短大圆插补。减小段长用于压低位置弦高误差；测试同时检查弦内位置与 SLERP 刀轴法向误差，而不是只检查 NC 点。

11. 姿态对轨迹拟合和速度前瞻的影响

11.1 应不应该考虑

应该。只要姿态在变，路径速度 v=ds/dt 就会映射为旋转轴速度；RTCP 又会把旋转带来的杠杆臂速度叠加到 XYZ 直线轴。纯 XYZ 前瞻不能证明五个物理轴都满足限制。

11.2 当前刀轴 SLERP 段的直接约束

刀轴相对参数 u 做匀角速度大圆插补，但反解后的 A/C 通常不是 u 的线性函数，尤其在极点附近不能只用端点 ΔA/L、ΔC/L 证明轴速度安全。应对实际逆解分支 q(s) 求导：

q̇ = q′(s)·ṡ
q̈ = q″(s)·ṡ² + q′(s)·s̈
q⃛ = q‴(s)·ṡ³ + 3q″(s)·ṡ·s̈ + q′(s)·s⃛

11.3 RTCP 耦合后的轴约束

物理轴是任务空间路径的函数 Q(s)=IK[p(s),R(s)]。工业前瞻通常直接在所选 IK 分支上计算：

Q̇ = Q′(s)·ṡ
Q̈ = Q″(s)·ṡ² + Q′(s)·s̈

对每个轴施加位置、速度、加速度和 jerk 约束，再反求允许的 ṡ、s̈、s⃛。这比只用姿态角速度更完整，因为 A/C 转动也会推高 XYZ 补偿轴速度。

当前缺口的准确表述 项目目前靠 NC 生成器离线估算 |ΔA|/(L/F) 和 |ΔC|/(L/F)，并用单元测试兜底。它尚未把 Q′、Q″、Q‴ 纳入在线 LookAheadPlanner，也没有对执行中的五轴命令做保持路径同步的统一时间缩放。

11.4 姿态对几何拟合的影响

若拟合删除或移动 XYZ 点，姿态也必须在同一参数域中重采样，并同时控制：

  • 位置弦高误差或轮廓误差。
  • 刀轴方向误差，例如 acos(ztool,fit·ztool,source)。
  • A/C 分支连续性和轴位置余量。
  • 拟合后 IK 轴速度、加速度与 jerk。

当前实现选择更保守的方式：有逐点姿态时禁止几何改变，而不是自动重采样姿态。

A/C 速度“毛刺”的当前首要原因 逐点姿态要求原始边不被拟合，因此球面行为树把 cornerTol 设为 0；同一个参数又被前瞻用于接点限速，结果是每段出口速度均为 0。短段反复启停形成速度尖峰。与此同时，A(u)、C(u) 在每段内线性、导数在段间不连续；即使 MovePath 只输出位置，Axis 层用于限速与反馈的位置差分速度仍会呈现尖锐变化。

13.1 典型报错

FAIL orientation count

姿态数量不是段数 + 1。检查行为树是否把 NcParse.orientations 正确连接到 PathMove.orientations。

FAIL geometry fitting changed edge

规划器简化、圆角或合并了带姿态的原始边。将容差设 0，或实现姿态随几何重采样。

FAIL orientation not representable

端点四元数含有 XYZAC 两旋转轴无法表示的 B 分量，或旋转次序不符合协议。

WARN soft limit reached

物理轴目标超出范围或制动距离不足。即使系统没有置故障，刀尖同步也可能已失真。

13.2 调参顺序

  1. 先验证所有 waypoint 的 IK、轴位置范围和 C 分支连续性。
  2. 再按位置和法向误差确定最大离散步长。
  3. 由段内 SLERP 采样和完整 IK 导数限制 F，端点 ΔA/L、ΔC/L 只作为快速粗检。
  4. 设置路径加速度、jerk，并检查段连接处物理轴导数。
  5. 最后才增加进给倍率；全过程监控是否触发轴级命令整形。

14.3 四元数插补该放在哪里

对于通用 6D 刀位，建议在 SO(3) 上使用最短弧 SLERP、SQUAD 或旋转向量样条，并用角速度/角加速度限制时间律。对于当前只有 A/C 两个旋转自由度的机床，最终仍应在选定且连续的 A/C 逆解分支上做轴约束。通用四元数插补可以保证空间姿态平滑，但不能替代机床轴分支与限位规划。

适合当前项目的下一步 优先把每段 A/C 速度约束加入 LookAheadPlanner::calculateLocalVelocityLimit 的输入数据，再增加 NRT 全路径 IK 预检。这样不会改变现有 RT 同步插补和 MovePath 协议，却能先消除最主要的在线超速风险。
