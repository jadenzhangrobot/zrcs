PLC 变量在线读写（RT ↔ GUI）实施方案

在 zrcs 实时进程与 GUI 之间打通 PLC 变量（IEC 61131-3）的读取上报与写入下发
方案 · 未实施 · 计划阶段 zrcs_rt / zrcs_nrt / zrcs_gui

1. 背景与目标

目前 PLC 由三个周期节点按序接入：PlcInputNode（INPUT）写输入，PlcLogicNode（OUTPUT，order=100）扫描，PlcOutputNode（OUTPUT，order=110）读输出。变量位于生成实例 ZRCS__DEMO 中，只存在于 RT 进程内，GUI 拿不到、也写不进。本方案后续打通「PlcOutputNode → SHM → ZMQ → GUI」的读取上报，与「GUI → ZMQ → SHM → PlcInputNode」的写入下发两条链路，供在线监控与调参。

当前状态：方案文档（本文件）。评审通过后按本文分阶段实施。

2. 现状链路（已探明，可直接复用）

2.1 数据流与现成模板

读（PLC→GUI，现成整链）: RT DataPub ──SHM──▶ RtBridge ──▶ StatusCollector ──▶ StatusPublisher(ZMQ PUB :5556, SystemStatus pb) ──▶ GUI ZmqStatusSubscriber ──▶ Qt 信号 ──▶ 面板 写（GUI→PLC，两条可复用模板）: 一次性命令: GUI ZMQClient(REQ:5555) → ZmqServer → CommandRouter → RtBridge.sendCommand → SHM cmdQueue → NodeFactory → CmdNode 周期参数 : NRT 生产者 push ──SHM ShmSPSC──▶ RT OutputNode 每周期 pop (MujocoParamUpdate 同款)
环节落点（文件）

3. 目标架构

══ 读（PLC 变量→GUI）══ PlcOutputNode(scan 后) ──lfl_write──▶ SHM: LockFreeLatest<PlcVariableData> plcVariables (kShmVersion→17) ──▶ NRT RtBridge.readPlcVariables() ──▶ StatusCollector.collect ──▶ SystemStatus.plc_variables ──▶ ZMQ:5556 ──▶ ZmqStatusSubscriber ── emit plcVariablesUpdated ──▶ PlcPanel(表格) ══ 写（GUI→PLC 变量）══ PlcPanel(值+按钮) ──▶ ZMQClient.sendCommand(REQ:5555) ──▶ ZmqServer ──▶ CommandRouter ──▶ 新增 plc 写处理 ──push──▶ SHM: ShmSPSC<PlcWriteData,kPlcWriteQueueCap> plcWriteQueue ──▶ RT PlcInputNode.run(scan 前) drain ──写──▶ ZRCS__DEMO 输入字段 ──▶ PlcLogicNode 扫描

4. 分阶段实施

P1 · 底层通道（RT ↔ SHM）——推荐先做

只改 zrcs_common + zrcs_rt，NRT/GUI 可后接。最小可验证闭环。

1.1 ShmLayout.h：新增 struct PlcVariableData（见 §5）、struct PlcWriteData；新增容量常量 kPlcWriteQueueCap=128（2 的幂）；SharedBlock 增 LockFreeLatest<PlcVariableData> plcVariables 与 ShmSPSC<PlcWriteData,kPlcWriteQueueCap> plcWriteQueue；kShmVersion 16→17。
1.2 PlcOutputNode.cpp：按需把生成实例中要暴露的字段收进 PlcVariableData；PlcInputNode.cpp 在扫描前通过 __SET_VAR 写入允许修改的输入字段。
1.3 在输入/输出节点的 onRegistered 分别建 ShmSPSCConsumer<PlcWriteData> 与 lfl_write 写端；输入节点扫描前有界消费写队列，输出节点扫描后 lfl_write 读变量。
1.4 构建 + 烟测（进程内写→读回）。

P2 · NRT 中继（SHM → ZMQ / ZMQ → SHM）

2.1 RtBridge：readPlcVariables()(lfl_read)、writePlcVariables(PlcWriteData)(push plcWriteQueue)。
2.2 message.proto：SystemStatus 增 repeated PlcVariable plc_variables（或独立 PlcStatus）；写入侧增 PLC 写消息（并入 TypedCommand oneof 或单独 PlcWriteCommand）。
2.3 StatusCollector/StatusPublisher 采集并序列化 plc_variables；CommandRouter 增写 PLC 处理。
2.4 全量重编译（SHM ABI 变更），联调 NRT+RT。

P3 · GUI 面板（zrcs_gui）

3.1 新增 zrcs_gui/modules/plc/PlcPanel.{h,cpp}：只读表格抄 AlarmPanel、数值/状态抄 JogControlPanel、写参抄 CommandPanel（QDoubleSpinBox+按钮→信号）。
3.2 resources/ui/main_window.ui 的 mainTabs 加 plcTab；MainWindow.cpp findChild+接线；接收新信号 plcVariablesUpdated，写走 sendMotionCommand/ZMQClient。
3.3 zrcs_gui/CMakeLists.txt 追加 SOURCES/HEADERS/UI_FILES。

5. 数据定义（P1）

// ShmLayout.h（示意，含 PLC 当前 I/O 的固定结构，后续可扩展）
struct PlcVariableData {
  uint64_t sequence   = 0;
  int32    axisCount  = 0;          // 生效轴数
  double   i_axisPos[8];            // ZRCS__DEMO.I_AXISPOS (LREAL，机床→PLC 实位)
  uint8_t  i_axisEnabled[8];        // ZRCS__DEMO.I_AXISENABLED
  uint8_t  q_running;               // ZRCS__DEMO.Q_RUNNING (PLC→机床)
  uint8_t  q_scanAlive;             // ZRCS__DEMO.Q_SCANALIVE
};
struct PlcWriteData {
  uint64_t seq;
  uint32_t varId;                  // 与固定结构/变量表对齐的下标
  double   value;
  uint8_t  valid;
};
// SharedBlock 内新增：
LockFreeLatest<PlcVariableData, ...> plcVariables;   // 读（RT 写/NRT 读）
ShmSPSC<PlcWriteData, kPlcWriteQueueCap> plcWriteQueue; // 写（NRT 写/RT 读）
约束：改动 SharedBlock 尺寸即改 ABI，kShmVersion 必须 16→17，且 RT/NRT/GUI（若直连）需同步重编译。GUI 若走 ZMQ（推荐）则无 ABI 负担。

6. 决策点（本方案采用推荐值，可调整）

决策点推荐备选
交付范围分阶段：P1 底层通道优先一次做全（含 GUI）改动面大
变量定义方式固定结构 PlcVariableData（先打通现有 I/O）通用动态变量表（name/类型/权限，工作量大）
GUI→PLC 写通道SPSC 写队列 + PlcInputNode 周期 pop（同 MujocoParamUpdate）一次性 cmdQueue 命令（args 无类型语义）
GUI 读数据源ZMQ SystemStatus（与全部现有监控一致）GUI 直连 SHM（打破现有约定、背 ABI）
写「PLC 内部变量」的限制：matiec 程序内部 VAR（如 MotionThreshold）不能跨进边界直接写；要让 GUI 可写，须在 .st 里把它声明为 VAR_INPUT 或定位变量，再由桥映射。因此“可写变量集”由 .st 暴露面决定，需在使用时注意/在面板标注。

8. 风险与约束

  • SHM ABI：SharedBlock 变更须 kShmVersion↗17 且全员重编；GUI 走 ZMQ 可规避。
  • 实时合规：写队列 drain 限条数（如每周期 ≤8），lfl_write 为无锁取最新，均符合 realtime 规范（无分配/无阻塞）。
  • 变量暴露边界：可写集取决于 .st 的输入/定位声明，需配套 .st 调整。
  • 测试：按项目记忆不改 test/，只列出对测试的影响；新增通道建议附进程内烟测。

9. 验证

  • P1：进程内置一组写值 → drain → 变量回读一致；时间推进单调。
  • P2：NRT 收 SystemStatus.plc_variables 与 RT 当前值一致；写消息落地后被 RT 消费。
  • P3：GUI PlcPanel 周期性显示变量、可写变量并回显；与轴/报警面板并行无冲突。
  • 全程 cmake --build（UCRT64，PATH 含 MSYS /usr/bin）构建通过。
