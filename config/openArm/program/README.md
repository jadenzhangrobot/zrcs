# openArm 行为树程序

`motion.xml` 是 openArm 双臂工程的行为树入口文件，可在 GUI 的“行为树编辑器”中打开。

轴号分配：

- `0-6`：左臂 7 个关节
- `7`：左夹爪
- `8-14`：右臂 7 个关节
- `15`：右夹爪

默认主树是 `Task_Pick_All_Objects_To_Bin`。加载 `motion.xml` 后直接执行 `START`，
左臂会依次抓取三件物品并放入框内。`OpenArm_Overview` 保留为不发送运动命令的安全
预览树，需要检查或编辑行为树但不希望机械臂运动时，可以手动切换到该子树。

## 桌面抓取行为树

`motion.xml` 提供以下左臂抓取子树：

- `Pick_Red_Block_To_Bin`：抓取红色方块并投放到框内左前区域。
- `Pick_Blue_Cylinder_To_Bin`：抓取蓝色圆柱并投放到框内右前区域。
- `Pick_Green_Sphere_To_Bin`：抓取绿色球体并投放到框内后侧区域。
- `Task_Pick_All_Objects_To_Bin`：使能左臂后依次执行上述三个子树。

完整任务的执行步骤：

1. 启动 RT MuJoCo 动力学后端，并在 GUI 中重新加载 openArm 场景。
2. 确认三个物件仍在 `robot.xml` 定义的初始位置，投放框中心为
   `(0.36, 0.22, 0.470)`。
3. 在行为树面板重新打开 `motion.xml`，确认带星标的默认页为
   `Task_Pick_All_Objects_To_Bin`。
4. 依次执行 `LOAD` 和 `START`。仿真默认**不发送 Enable**，直接运动。
5. 任务结束后停在安全高位 stage；真机需要失能时再手动跑 `Disable_Left_Arm`。

## 路径策略

home 腕部位姿约 `(0, 0.1225, -0.436)`，世界高度约 `0.26 m`，低于桌面 `0.375 m`。
直接笛卡尔直线去桌面会穿桌，也会触发贴边 IK 问题。

当前流程：

1. `MoveAbs` 抬肩 `j1=-1.0`（先把世界高度抬过桌面）
2. `MoveAbs` 弯肘 `j3=1.4` 到安全高位 stage
3. 全程 `MoveJ` PTP：接近 → 夹取 → 抬升 → 投放 → 撤离 → 回 stage
4. 夹爪与 PTP 使用较高速度（约 `0.7~1.4` 轴速比例 / 夹爪 `1.5~2.0 rad/s`）

完整任务只在开头抬升一次；每件结束后回 stage。单独跑某个 `Pick_*` 时，子树内部
也会先执行 `Lift_To_Safe_Height`。

抓取目标是机械臂腕部坐标（经 IK 验证的构型），不是直接填 `robot.xml` 世界坐标。
红/蓝/绿路径的关节插补已用 MuJoCo 对桌面与投放框做过静态碰撞采样。

当前流程是固定坐标抓取，没有视觉/力觉。物件被挪动后需要同步改接近点与夹取点。

## 夹取与“假体感”

物件在 MuJoCo 中是带质量和碰撞的 freejoint 实体。若夹爪像穿过物体：

- 先确认仿真为动力学模式（未开 `kinematicOnly`）
- 夹爪闭合目标不要用绝对 0，当前为 `0.08 rad` 持续夹紧
- 闭合后等待约 `450 ms` 再抬升
- 物件/桌面接触摩擦与硬度已加强；夹爪伺服 `kp` 已提高到 120

完全垂直向下姿态在当前桌面坐标附近 IK 很难解出；现姿态是可达的斜向下折中。

当前 `MoveAbsJ` 的命令参数只包含 `J1-J6`，不能完整控制 openArm 的 7 关节单臂。
因此示例采用 `MoveAbs` 单轴运动，没有提供可能发生参数越界的 `MoveAbsJ Count=7` 配置。
